## Context

Implementation plan I-5, I-6, and I-9, discussion.md, and overview.md Security required defining archive copy verification and destination filename collision handling.

## Alternatives

1. Verify with SHA-256 and skip with a conflict report on differing content without renaming
2. Verify by file size and modification date and overwrite existing archive files on collision

## Decision

Verify archived copies using SHA-256 checksums. On destination filename collision: if SHA-256 matches, skip copying and treat the file as already verified-archived; if content differs, write the copy using a unique numeric suffix (e.g. 'name (2).ext') and never overwrite existing archived files.

## Reason

Confirmed by the user in conversation to guarantee byte-for-byte archive integrity and prevent silent data loss on filename collisions.

## Consequences

Archive operations compute SHA-256 hashes of source and copied files to verify integrity before recording a verified archive copy eligible for subsequent confirmed original removal. Existing files in destinations are never overwritten.
