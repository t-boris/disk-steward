## Context

User reported slow scanning, repeated rescans when switching folders/disks, and severe UI lag when drilling into folders in Storage Explorer.

## Alternatives

1. Rescan from scratch on every folder/disk visit and recompute treemap/breakdowns synchronously on the Main Thread

## Decision

Accelerate storage scanning with parallel POSIX traversal, cache scanned storage trees in memory and compressed on-disk snapshots, watch cached roots with macOS FSEvents to invalidate stale caches on filesystem changes, and precompute folder breakdowns off the Main Thread with isolated local hover state.

## Reason

Explicit user requirement that Storage Explorer feel instantaneous, reuse cached scans across navigation, and invalidate caches automatically when filesystem updates occur.

## Consequences

StorageScanner uses parallel POSIX opendir/readdir/lstat with O(1) (dev, ino) deduplication; StorageNode uses reference semantics with O(1) equality; ScanCacheManager caches scanned trees in memory and LZFSE-compressed disk snapshots; FileSystemWatcher uses macOS FSEvents to detect filesystem mutations and invalidate affected cache entries; and StorageExplorerView computes inspector snapshots off the Main Thread with local hover state for 120 FPS responsiveness.
