## Context

Users configuring an archive job with no classification rules and a fallback destination (e.g., archiving ~/Documents to Archive/Documents) saw all nested files flattened into a single flat list because fallback routing hardcoded preserveRelative = false and ArchiveRule defaulted preserveRelativeSubpath to false.

## Alternatives

1. Always flatten files into the target folder unless a per-rule override is enabled
2. Always preserve folder structure with no option to flatten

## Decision

Preserve relative source folder hierarchy by default (true) for both fallback destinations (controlled by a job-level preserveFolderStructure setting) and new classification rules (controlled per rule via preserveRelativeSubpath), with clear UI toggles so users can explicitly opt into flat output when desired.

## Reason

Requested by the user after archiving ~/Documents into a fallback folder produced a flat list instead of preserving the Documents directory tree.

## Consequences

ArchiveJob gains a persisted preserveFolderStructure setting defaulting to true (backward-compatible decodeIfPresent ?? true for existing saved jobs), applied to fallback destination archiving and exposed in the job editor and detail views. Individual ArchiveRule entries also default preserveRelativeSubpath to true and allow toggling subfolder preservation per rule.
